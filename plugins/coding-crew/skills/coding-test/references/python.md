# Python

## Определить, что используется

1. `pyproject.toml` → `[tool.pytest.ini_options]`, `[tool.coverage.*]`, зависимости; `tox.ini`, `setup.cfg`, `pytest.ini`, `Makefile`;
2. существующие тесты: `pytest` (голые функции + `assert`) или `unittest` (`class TestX(TestCase)`);
3. менеджер окружения — `poetry`, `uv`, `pdm`, `pipenv` или голый `venv`. Запускай тесты его командой (`poetry run pytest`, `uv run pytest`), иначе рискуешь взять другой интерпретатор и другие версии зависимостей;
4. CI-конфиг — что гоняется на PR.

Работай в окружении проекта. Ставить пакеты в системный python — почти всегда ошибка: тесты пройдут у тебя и упадут у всех остальных.

## Команды

```bash
pytest                                   # весь набор
pytest tests/test_auth.py::test_login    # один тест
pytest -k "login and not slow"           # по выражению
pytest -x -q                             # стоп на первом падении, кратко
pytest --lf                              # только упавшие в прошлый раз
pytest -p no:randomly                    # отключить случайный порядок (для диагностики)
pytest -n auto                           # параллельно, если есть pytest-xdist
```

При диагностике падения полезны `-vv` (полный diff ассерта) и `--tb=short`.

## Покрытие

```bash
pytest --cov=<пакет> --cov-report=xml --cov-report=term-missing
python scripts/diff_coverage.py --coverage coverage.xml --base origin/main --min 80
```

Формат `xml` (Cobertura) и `json` (`--cov-report=json` → `coverage.json`) оба читаются скриптом. `term-missing` полезен сразу: показывает номера непокрытых строк в консоли.

`--cov` без аргумента покрывает всё подряд, включая зависимости, — указывай пакет явно.

## Конвенции

- Расположение: `tests/` зеркалом структуры пакета либо `test_*.py` рядом с модулем. Следуй тому, что уже есть.
- Именование: файлы `test_*.py`, функции `test_*`. Имя — утверждение: `test_returns_401_when_password_wrong`.
- Общие фикстуры — `conftest.py`; он подхватывается автоматически по дереву каталогов. Загляни туда до того, как писать свою фикстуру: скорее всего половина уже есть.
- Параметризация вместо копипасты:

```python
@pytest.mark.parametrize(
    ("value", "expected"),
    [("", False), ("a@b.co", True), ("a@", False)],
    ids=["empty", "valid", "no_domain"],
)
def test_validate_email(value, expected):
    assert validate_email(value) is expected
```

`ids` стоят усилий: без них падение выглядит как `test_validate_email[value2-False]`.

## Моки

- `unittest.mock.patch` — патчь **там, где объект используется**, а не там, где определён: `patch("myapp.service.requests.get")`, не `patch("requests.get")`. Это причина примерно половины «мок не сработал».
- Предпочитай `monkeypatch` (фикстура pytest) — она сама откатывает изменения после теста.
- Время: `freezegun` (`@freeze_time("2026-01-01")`) или подмена вызываемого `now`. Лучший вариант — если код принимает `clock`/`now` параметром, тогда мок не нужен вовсе.
- HTTP: `responses` или `respx` (для httpx). Они проверяют и то, какой запрос ушёл.
- `autospec=True` в `patch` ловит вызов мока с неправильной сигнатурой — без него мок радостно примет что угодно и тест ничего не заметит.

## Типичные грабли

**Мутируемое значение по умолчанию в фикстуре.** Общий словарь или список протекает между тестами. Возвращай новый объект на каждый вызов фикстуры.

**Голый `assert something`.** При падении не видно, что было получено. Проверяй конкретное значение: `assert resp.status_code == 401`.

**`pytest.raises` без проверки сообщения.** `with pytest.raises(ValueError)` пройдёт на любой `ValueError`, включая опечатку в коде теста. Добавляй `match=`.

**Асинхронные тесты без плагина.** `async def test_...` без `pytest-asyncio` (или `anyio`) молча пропускается как «не корутина» — набор зелёный, тесты не выполнялись. Проверь, что тест реально запускался (`-v` покажет `PASSED`, а не `SKIPPED`).

**Порядок и глобальное состояние.** Модульные синглтоны, кеши `lru_cache`, переменные окружения. `pytest-randomly` (если стоит) вскрывает такие связи; при диагностике отключай его через `-p no:randomly`.

## Интеграционные тесты

- БД: `testcontainers` для настоящей базы либо фикстура с транзакцией и откатом. Sqlite вместо postgres быстрее, но не ловит диалектные различия — если тест про SQL, бери настоящую БД.
- Веб: `TestClient` (FastAPI/Starlette) или `django.test.Client` — реальный порт не нужен.
- Файловая система: фикстура `tmp_path`, а не `/tmp` руками, — она сама убирается и не даёт тестам мешать друг другу.
- Переменные окружения: `monkeypatch.setenv`, не `os.environ[...] = ...` (второе протечёт в соседние тесты).

## Mutation

`mutmut` или `cosmic-ray`, если уже настроены:

```bash
mutmut run --paths-to-mutate src/changed_module.py
mutmut results
```

Не настроены — не ставь ради одного прогона, ограничься точечной проверкой чувствительности.
