# Go

## Определить, что используется

Стандартная библиотека покрывает почти всё: `testing` + `go test`. Смотри `go.mod` на дополнения — обычно это `testify` (ассерты), `gomock`/`mockery` (моки), `testcontainers-go`, `httptest` (в stdlib), `golden`-файлы.

Проверь `Makefile` и CI-конфиг: там обычно зафиксированы флаги (`-race`, теги сборки, таймаут), и твой прогон должен им соответствовать, иначе локально зелено, а в CI красно.

Если в проекте есть `testify` — используй его; если нет, не тащи зависимость ради ассертов, стандартный стиль `if got != want { t.Errorf(...) }` здесь норма, а не бедность.

## Команды

```bash
go test ./...                              # весь модуль
go test ./internal/auth/...                # пакет и вложенные
go test -run 'TestLogin/wrong_password'    # конкретный тест и подтест
go test -race ./...                        # детектор гонок — на всём, что работает с горутинами
go test -count=1 ./...                     # без кеша результатов
go test -v ./internal/auth                 # подробный вывод
go test -shuffle=on ./...                  # случайный порядок тестов
```

`-count=1` — единственный надёжный способ обойти кеш: Go запоминает успешные прогоны и может вернуть старый результат, из-за чего кажется, что новый тест «сразу зелёный».

## Покрытие

```bash
go test ./... -coverprofile=coverage.out -covermode=atomic
go tool cover -func=coverage.out              # проценты по функциям
python scripts/diff_coverage.py --coverage coverage.out --base origin/main --min 80
```

`-covermode=atomic` обязателен вместе с `-race`. По умолчанию покрытие считается только по тестируемому пакету — если тесты одного пакета покрывают код другого, добавь `-coverpkg=./...`.

## Конвенции

- Файлы `*_test.go` лежат рядом с кодом. Пакет `foo` — доступ к приватному; пакет `foo_test` — только публичный API, что обычно лучше: тест не цепляется за внутренности.
- **Табличные тесты** — доминирующий стиль, следуй ему:

```go
func TestValidateEmail(t *testing.T) {
    tests := []struct {
        name  string
        input string
        want  bool
    }{
        {"empty", "", false},
        {"valid", "a@b.co", true},
        {"no domain", "a@", false},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := ValidateEmail(tt.input); got != tt.want {
                t.Errorf("ValidateEmail(%q) = %v, want %v", tt.input, got, tt.want)
            }
        })
    }
}
```

Сообщение об ошибке в формате `got = X, want Y` с входными данными — местная норма; по нему падение читается без отладчика.

- `t.Helper()` в вспомогательных функциях — иначе номер строки в отчёте указывает на хелпер, а не на тест.
- `t.Cleanup(func(){...})` вместо `defer` для уборки — работает и в подтестах, и при `t.Fatal`.
- `t.Parallel()` ускоряет набор, но требует, чтобы тест не зависел от общего состояния; в табличных тестах не забывай про захват переменной цикла (в Go до 1.22 — `tt := tt`).

## Моки

- Интерфейс, объявленный **на стороне потребителя**, — идиоматичный способ подмены; часто ручная заглушка в 5 строк лучше сгенерированного мока.
- `net/http/httptest` — и для сервера (`httptest.NewServer`), и для обработчика (`httptest.NewRecorder`). Реальный порт не нужен.
- Время: не вызывай `time.Now()` в бизнес-логике напрямую — передавай `clock func() time.Time` или интерфейс. Это дешевле любого мока и делает тест детерминированным.
- `context.WithTimeout` в тестах: не полагайся на реальные задержки, они делают тест медленным и мигающим.

## Типичные грабли

**Забытый `-count=1`.** Кеш возвращает прошлый успех, и правка теста не проверяется.

**Ошибка проверяется как `err != nil`.** Проходит на любой ошибке, включая не ту. Используй `errors.Is` / `errors.As` и проверяй конкретный тип или сентинел.

**Горутина, пережившая тест.** Тест зелёный, но состояние течёт в соседний. `-race` ловит часть таких случаев; `t.Cleanup` с остановкой — остальные.

**Сравнение структур через `==` или `reflect.DeepEqual` там, где нужен `cmp.Diff`.** `go-cmp` даёт читаемый diff при падении и умеет игнорировать неэкспортируемые поля.

**Golden-файлы, обновляемые по привычке.** Флаг `-update` удобен, но тест на golden фиксирует что угодно, включая баг. Для логики пиши явные ассерты.

## Интеграционные тесты

- Тег сборки для медленных тестов: `//go:build integration`, запуск `go test -tags=integration ./...`. Проверь, гоняет ли CI этот тег, — иначе тесты не защищают ничего.
- БД: `testcontainers-go` либо реальная база из docker-compose. Транзакция с откатом в `t.Cleanup` — самый дешёвый способ изоляции.
- `testing.Short()` + `-short` — стандартный способ пропускать тяжёлое: `if testing.Short() { t.Skip("skipping integration test") }`.

## Mutation

`go-mutesting`, если уже используется в проекте:

```bash
go-mutesting ./internal/changed/...
```

Не используется — не ставь ради одного прогона, ограничься точечной проверкой чувствительности.
