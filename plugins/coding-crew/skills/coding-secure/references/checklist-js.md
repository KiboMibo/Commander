# Чек-лист: JavaScript / TypeScript (Node, React)

Проходи от точек входа. Пункты отсортированы по тому, как часто они оказываются настоящими блокерами, а не по классификациям.

## Инъекции и выполнение кода

- **SQL.** Конкатенация или шаблонная строка в `db.raw()`, `query()`, `sequelize.query()`, `$queryRawUnsafe`. ORM защищает только пока используется её builder: `whereRaw(\`name = '${name}'\`)` — инъекция. Ищи по `raw`, `Unsafe`, `${` внутри SQL-строк.
- **NoSQL.** MongoDB принимает объекты: если `req.body.filter` уходит в `find()` без приведения типов, `{"$ne": null}` обходит проверку. Особенно опасно в логине: `User.findOne({email, password: req.body.password})`.
- **Команды.** `child_process.exec`/`execSync` со строкой — интерполяция пользовательского ввода даёт RCE. `execFile`/`spawn` с массивом аргументов безопасны, пока не включён `shell: true`.
- **Код.** `eval`, `new Function`, `vm.runInThisContext`, `setTimeout` со строкой. В шаблонизаторах — интерполяция пользовательского ввода в сам шаблон, а не в данные (Handlebars, EJS, Pug).
- **Пути.** `path.join(base, req.params.file)` не защищает от `../`. Нужен `path.resolve` плюс проверка, что результат начинается с базовой директории. Ищи по `readFile`, `createReadStream`, `sendFile`, `res.download`.

## Прототипное загрязнение и десериализация

- Рекурсивный merge/clone/set без фильтрации `__proto__`, `constructor`, `prototype`. Уязвимы самописные `deepMerge`, старые `lodash.merge`, парсеры query-строк с поддержкой вложенности.
- `JSON.parse` от пользователя, результат которого потом используется как ключи объекта или сливается с конфигом.
- Библиотеки сериализации, восстанавливающие произвольные классы (`node-serialize`, `serialize-javascript` в небезопасном режиме).

## Аутентификация и авторизация

- **Middleware реально применён.** Проверь порядок: роут, зарегистрированный до `app.use(requireAuth)`, не защищён. Отдельно смотри роуты, вынесенные в другой роутер или подключённые напрямую.
- **Проверка объекта, а не только входа.** `GET /orders/:id` с `findById(req.params.id)` без сверки владельца — IDOR. Ищи все места, где идентификатор берётся из запроса и сразу идёт в поиск по БД.
- **JWT.** Алгоритм зафиксирован явно (`algorithms: ['RS256']`), иначе возможна подмена на `none` или переключение на HMAC с публичным ключом. Проверяются `exp`, `iss`, `aud`. Секрет из окружения. Есть механизм отзыва или короткий срок жизни.
- **Cookie сессии.** `httpOnly`, `secure`, `sameSite: 'lax'` или строже, разумный `maxAge`. `domain` не шире, чем нужно.
- **Смена пароля / e-mail** инвалидирует существующие сессии и токены сброса.

## XSS и фронтенд

- `dangerouslySetInnerHTML`, `v-html`, `innerHTML`, `document.write` с данными, пришедшими от пользователя или из API.
- Ссылки: `href={userUrl}` допускает `javascript:`. Нужна проверка схемы.
- `target="_blank"` без `rel="noopener noreferrer"` в старых сборках.
- Данные, вставляемые в SSR-разметку через `JSON.stringify` без экранирования `<`/`>` — разрыв тега `</script>`.
- CSP: есть ли заголовок вообще, нет ли `unsafe-inline`/`unsafe-eval`, не сведён ли к `*`.
- Секреты в бандле: всё под `NEXT_PUBLIC_`/`VITE_`/`REACT_APP_` попадает в браузер. Приватный ключ там — блокер.

## Секреты и конфигурация

- Захардкоженные строки подключения (`postgres://user:pass@host`), API-ключи, приватные ключи в исходниках, тестах, снапшотах, `docker-compose.yml`.
- `.env` в репозитории или отсутствие его в `.gitignore`. `.env.example` со значениями вместо плейсхолдеров.
- Ключи в комментариях и в закомментированном коде — сканеры их часто пропускают.

## Сетевое взаимодействие

- **SSRF.** `fetch`/`axios` по URL из запроса. Проверь, что есть allow-list доменов и запрет на приватные диапазоны (включая `169.254.169.254` — метаданные облака) и что запрет переживает редиректы.
- **TLS.** `rejectUnauthorized: false`, `NODE_TLS_REJECT_UNAUTHORIZED=0`, кастомный `httpsAgent` без проверки. В продакшен-коде — важная находка, в тестах — замечание.
- **CORS.** `origin: true` или отражение `Origin` из запроса вместе с `credentials: true` — это эквивалент отсутствия защиты.
- **Редиректы.** `res.redirect(req.query.next)` без allow-list — open redirect, ступенька для фишинга и обхода OAuth.

## Утечки данных

- Логирование целиком: `console.log(req.body)`, `logger.info(user)` с полями пароля/токена, логирование заголовков с `Authorization`.
- Обработчик ошибок, отдающий `err.stack` или текст SQL клиенту в продакшене.
- Сериализация пользователя в ответ без выборки полей — `passwordHash`, `resetToken`, внутренние флаги уходят наружу. Ищи возврат объекта БД напрямую.
- Различающиеся ответы на «нет такого пользователя» и «неверный пароль» — перебор аккаунтов.

## Прочее

- Отсутствие ограничения частоты на логине, сбросе пароля, отправке кодов.
- Загрузка файлов: проверка типа по расширению вместо содержимого, отсутствие лимита размера, сохранение под именем из запроса, отдача из директории со статикой без `Content-Disposition`.
- `crypto.randomBytes` вместо `Math.random` для токенов, кодов и идентификаторов сессий.
- Сравнение секретов через `===` вместо `crypto.timingSafeEqual` — актуально для проверки HMAC-подписей вебхуков.
- Пароли: argon2/bcrypt/scrypt, а не sha256 и тем более md5.
