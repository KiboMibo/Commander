# Чек-лист: Docker, Kubernetes, CI, Terraform

Инфраструктурные находки часто серьёзнее прикладных: открытый в мир порт или секрет в CI обходит любую валидацию в коде. При этом они обычно чинятся одной строкой, поэтому дёшевы для исполнителя — не занижай их из-за «это же просто конфиг».

## Dockerfile

- **Секреты в слоях.** `ARG`/`ENV` с ключами, `COPY .env`, `RUN git clone https://token@...`, `RUN pip install --index-url https://user:pass@...`. Слой сохраняет значение навсегда, даже если следующий слой его удаляет. `docker history` показывает всё. Использовать надо `RUN --mount=type=secret`.
- **`COPY . .` без `.dockerignore`** — в образ уезжают `.git` (вся история с секретами), `.env`, ключи разработчика, `node_modules` с чужим кодом. Проверь наличие `.dockerignore` и что `.git` в нём есть.
- **Пользователь.** Нет `USER` — контейнер работает от root. В сочетании с монтированием томов и уязвимостью в приложении это выход за пределы контейнера.
- **Базовый образ.** Тег `latest` или плавающий тег — невоспроизводимая сборка. Устаревший образ (`node:14`, `python:3.7`) тянет непатченные системные библиотеки. Идеально — digest.
- **Лишнее в рантайме.** Компиляторы, `curl`, `git`, отладочные утилиты в финальном образе расширяют возможности атакующего. Multi-stage сборка.
- `apt-get install` без `--no-install-recommends` и без очистки списков — не безопасность, а размер; в отчёт не тащи.

## Kubernetes

- **`securityContext`.** `privileged: true` — фактически root на ноде, блокер. Дальше: `allowPrivilegeEscalation: false`, `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `capabilities.drop: [ALL]`.
- **Монтирование хоста.** `hostPath` (особенно `/`, `/var/run/docker.sock`, `/proc`), `hostNetwork`, `hostPID` — выход из изоляции.
- **Секреты.** `Secret` в git в открытом виде (`data` — это base64, а не шифрование). Секреты в `env` манифеста вместо `secretKeyRef`. Отсутствие sealed-secrets/external-secrets при хранении манифестов в репозитории.
- **RBAC.** `ClusterRole` с `*` в `resources`/`verbs`, привязка к `system:masters`, `ServiceAccount` с правами больше нужных, `automountServiceAccountToken` не отключён там, где токен не нужен.
- **Сеть.** Отсутствие `NetworkPolicy` — все поды ходят друг к другу. `Service` типа `LoadBalancer`/`NodePort` для внутреннего сервиса — публикация наружу.
- **Ресурсы.** Нет `limits` — один под роняет ноду. Это доступность, отмечай как важное, если сервис публичный.
- Ingress без TLS, с `ssl-redirect: false`, с аннотациями, отключающими проверки.

## CI/CD

- **Секреты в конфиге.** Ключи прямо в `.github/workflows/*.yml`, `.gitlab-ci.yml`, `Jenkinsfile` — блокер плюс ротация.
- **Секреты в логах.** `echo $TOKEN`, `set -x` рядом с секретами, вывод переменных окружения при отладке. Логи CI часто публичны для всей команды, а в open source — для всех.
- **`pull_request_target` в GitHub Actions** — выполняет workflow из базовой ветки с секретами, но с кодом PR. В сочетании с `actions/checkout` на `head.sha` это выполнение чужого кода с доступом к секретам. Блокер.
- **Незакреплённые действия.** `uses: some/action@main` — владелец действия может поменять код в любой момент. Закрепляй по SHA-коммита для сторонних действий.
- **Права `GITHUB_TOKEN`.** Умолчание `write-all` в старых репозиториях; должно быть `permissions: contents: read` с точечными расширениями.
- **Выполнение недоверенного ввода.** Интерполяция `${{ github.event.pull_request.title }}` внутри `run:` — заголовок PR попадает в shell. Классическая инъекция в Actions; передавай через `env:`.
- Кэш, доступный на запись из форков; артефакты сборки, содержащие `.env` или ключи подписи.

## Terraform и облако

- **Секреты в состоянии.** `terraform.tfstate` содержит значения в открытом виде. Файл в git — блокер. Бэкенд должен быть удалённый, с шифрованием и ограниченным доступом.
- **Хардкод.** `password = "..."` в `.tf`, ключи доступа в `provider`. Даже с переменными: `.tfvars` в репозитории.
- **Публичный доступ.** S3 без `block_public_access`, бакет с ACL `public-read`, база с `publicly_accessible = true`.
- **Сетевые правила.** `0.0.0.0/0` для портов 22, 3389, 5432, 6379, 27017, 9200. Для 443 это нормально, для БД — блокер.
- **IAM.** `Action: "*"` c `Resource: "*"`, `AdministratorAccess` на сервисные роли, роли без условий доверия.
- **Шифрование и журналирование.** Диски и бакеты без шифрования, отсутствие логов доступа, отключённый versioning на бакетах с важными данными.

## Что смотреть в отчёте отдельно

Инфраструктурные находки часто относятся к файлам, которые «не менялись» и потому выпадают из ревью диффа. При полном аудите проходи по ним всегда; при ревью диффа проходи, если менялись сами конфиги или добавлялся новый сервис, порт, том, секрет.

Для каждой находки указывай, **где это применяется**: правило в `main.tf`, применённое только в стенде разработки, и то же правило в продакшене — разные уровни. Если по репозиторию этого не видно, так и напиши: «уровень зависит от того, применяется ли модуль в продакшене — уточнить».
