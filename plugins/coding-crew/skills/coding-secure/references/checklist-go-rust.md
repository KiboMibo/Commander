# Чек-лист: Go и Rust

Оба языка снимают целые классы проблем (управление памятью в Rust, отсутствие исключений в Go), поэтому уязвимости смещаются в логику, конкурентность и обработку ошибок. Не ищи здесь то же, что в скриптовых языках.

## Go

### Инъекции и внешние вызовы

- `fmt.Sprintf` в SQL вместо плейсхолдеров `$1`/`?`. `database/sql` параметризует сам, пока строку не собрали руками. Имена таблиц и колонок параметризовать нельзя — только allow-list.
- `exec.Command("sh", "-c", userInput)` — RCE. Безопасная форма — команда и аргументы отдельными элементами без оболочки.
- `text/template` вместо `html/template` для HTML-вывода: первый не экранирует, и это тихая XSS.
- `filepath.Join` не защищает от `..`. Нужен `filepath.Clean` плюс проверка префикса через `strings.HasPrefix(abs, base)` после `filepath.Abs`.
- SSRF: `http.Get` по URL из запроса. Ограничивай доменами, запрещай приватные диапазоны, контролируй редиректы через `CheckRedirect`.

### Обработка ошибок

Главный источник дыр в Go — проигнорированная ошибка. Смотри на `_ =` и на вызовы без проверки `err`:

- ошибка верификации токена/подписи проигнорирована — проверка не выполняется вовсе;
- ошибка от `rand.Read` проигнорирована, буфер остаётся нулевым — предсказуемый токен;
- `defer resp.Body.Close()` без проверки `err` до него — паника на nil.

Отдельно: `panic` в HTTP-хендлере без `recover` роняет обработку (в `net/http` recover есть на уровне соединения, во многих фреймворках — нет).

### Конкурентность

- Общая map или счётчик без мьютекса под конкурентными запросами — гонка. Прогоняй `go test -race`, если тесты есть.
- Проверка-и-действие в две операции над общим состоянием (проверил баланс → списал) — гонка с последствиями в деньгах. Нужна транзакция БД или блокировка.
- Захват переменной цикла в горутине (до Go 1.22) — обработка не тех данных.

### Криптография и секреты

- `math/rand` вместо `crypto/rand` для токенов, идентификаторов сессий, кодов.
- `InsecureSkipVerify: true` в `tls.Config` — отключённая проверка сертификата.
- Сравнение подписей через `==` вместо `hmac.Equal` / `subtle.ConstantTimeCompare`.
- Пароли: `golang.org/x/crypto/bcrypt` или argon2, не `sha256`.
- Захардкоженные ключи в константах и в `//go:embed` конфигах.

### HTTP-слой

- Middleware аутентификации навешен на все нужные роуты; проверь маршруты, зарегистрированные отдельно от основной группы.
- Проверка владельца объекта, а не только факта аутентификации.
- Таймауты на `http.Server` (`ReadTimeout`, `WriteTimeout`) и на клиенте — без них тривиальный отказ в обслуживании.
- Лимит размера тела запроса: `http.MaxBytesReader`.
- Ответы об ошибках не содержат внутренние пути и текст запроса.

## Rust

Компилятор закрывает память, поэтому смотри на границы, где гарантии отключаются или не действуют.

- **`unsafe`.** Каждый блок — предмет отдельного внимания: есть ли комментарий с обоснованием инварианта, проверяются ли длины и выравнивание, не приходит ли длина из внешних данных. FFI-границы (`extern "C"`, `CStr::from_ptr`) — самое частое место реальных проблем.
- **Паники как отказ в обслуживании.** `unwrap`, `expect`, индексация среза, `slice[a..b]` с границами из запроса, целочисленное деление. В сервисе, где паника роняет воркер или соединение, это важная находка. В release-сборке арифметическое переполнение не паникует, а заворачивается — для расчётов денег и размеров используй `checked_*`/`saturating_*`.
- **Десериализация.** `serde` с `#[serde(deny_unknown_fields)]` там, где лишние поля не должны проходить; ограничение размера входных данных до разбора; отсутствие рекурсивных структур без лимита глубины.
- **SQL.** `sqlx::query!` и `diesel` параметризуют; склейка строк для `query()` — инъекция.
- **Команды.** `Command::new("sh").arg("-c").arg(input)` — RCE. Аргументы передавай отдельно.
- **Криптография.** `rand::thread_rng` подходит для токенов (это CSPRNG), но `rand::random` в старых версиях и самописные генераторы — нет. Пароли — `argon2`. Сравнение секретов — `subtle::ConstantTimeEq`.
- **TLS.** `danger_accept_invalid_certs(true)` в `reqwest`, кастомный verifier, принимающий всё.
- **Зависимости.** `cargo audit` по `Cargo.lock`; отдельно посмотри крейты с большим количеством `unsafe` и малым числом мейнтейнеров, а также `build.rs`, выполняющийся при сборке.

## Общее для обоих

- Секреты в исходниках, тестах и конфигах сборки.
- Логирование структур целиком: реализованный `Debug`/`String` может печатать токены. Проверь, что чувствительные поля скрыты (в Rust — ручной `Debug`, в Go — не логировать структуру целиком).
- Отсутствие ограничения частоты на аутентификации.
- Работа с временем и токенами: срок жизни проверяется, отзыв возможен.
