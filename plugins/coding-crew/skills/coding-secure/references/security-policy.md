# Файл правил проекта: `.security-policy.md`

Необязательный файл в корне репозитория, где команда фиксирует свои решения по безопасности. Смысл в том, что общие эвристики не знают контекста: пакет, который в одном проекте запрещён политикой, в другом стоит по договорённости с командой безопасности; риск, который выглядит важным, может быть уже осознанно принят с обоснованием.

Без этого файла скилл каждый раз находит одно и то же, команда каждый раз объясняет, почему это так, — и отчёт постепенно перестают читать.

## Как использовать при ревью

Прочитай файл в первой фазе, до прогона сканеров. Дальше:

- **Запрещённые пакеты** — присутствие любого из них становится находкой, даже если у пакета нет CVE. Уровень берётся из политики; если не указан — важная.
- **Принятые риски** — находка, совпадающая с записью, в основной список не идёт. Упомяни её одной строкой в разделе «Проверенное и чистое» со ссылкой на решение: «SSRF в `fetchPreview` — принятый риск, см. `.security-policy.md`, срок пересмотра 2026-09». Если срок пересмотра истёк — верни в находки как замечание с пометкой, что решение просрочено.
- **Лицензии** — сверяй список зависимостей с разрешёнными. Без политики лицензии просто отмечаются, а не оцениваются.
- **Особые области** — места, помеченные как требующие повышенного внимания, проверяй тщательнее и всегда упоминай в отчёте, даже если чисто.

Политика не может отменить блокирующую находку с доказанной эксплуатируемостью — если запись явно противоречит очевидной дыре, вынеси это отдельным пунктом: возможно, риск принимали при других условиях.

## Формат

Файл в свободном markdown; скилл ориентируется по заголовкам. Рабочий образец:

```markdown
# Правила безопасности проекта

## Запрещённые пакеты

| Пакет | Причина | Чем заменять | Уровень |
|---|---|---|---|
| `request` | не поддерживается с 2020 | `undici` | важная |
| `md5` | не для паролей и подписей | `argon2`, `sha256` из `node:crypto` | блокирующая |
| `moment` | заброшен, тянет всю локаль | `date-fns` | замечание |

## Разрешённые лицензии

MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC.
Всё остальное — согласование с юристами до добавления.

## Принятые риски

### SSRF в `src/services/preview.ts`

Сервис ходит по пользовательским URL для превью ссылок. Ограничен списком доменов
и работает в изолированной подсети без доступа к внутренним адресам.
Решение: команда платформы, 2026-03-14. Пересмотр: 2026-09-14.

### Отключён CSRF на `/api/webhooks/*`

Вебхуки от внешних систем проверяются по HMAC-подписи, cookie-сессия там не используется.
Решение: 2026-01-20. Пересмотр: не требуется.

## Области повышенного внимания

- `src/billing/**` — работа с деньгами, любые изменения проверять на гонки и двойное списание
- `src/auth/**` — выпуск и отзыв токенов
- `migrations/**` — права на таблицы, обратимость

## Секреты

Все секреты — только через переменные окружения и хранилище CI.
`.env` в `.gitignore`, `.env.example` содержит только имена без значений.
Ротация при любом попадании в коммит — обязательна и немедленна.
```

## Если файла нет

Ничего не меняется — работают общие эвристики. Но если по ходу ревью стало ясно, что в проекте есть устойчивые договорённости (повторяющиеся исключения в конфигах сканеров, комментарии `// security: ok, reviewed`, обсуждения в `CONTRIBUTING.md`), предложи в конце отчёта завести файл и покажи, что в нём стоило бы зафиксировать. Это разовое вложение, которое снимает шум во всех следующих ревью.
