# Шаблон отчёта об изменениях

Отчёт живёт в `docs/reports/<ID-или-слаг>-<YYYY-MM-DD>.md` и одновременно служит телом MR/PR.

Он пишется для человека, который не следил за работой. Его вопросы в порядке возникновения: *что изменилось → почему так → это точно работает → куда смотреть, чтобы не пропустить проблему.* Разделы отвечают ровно на них.

Соразмерность важна: правка в одном файле — отчёт на пятнадцать строк. Волна из пяти задач — полный формат. Раздел, которому нечего сказать (нет метрик, нет отвергнутых альтернатив), убирается целиком, а не заполняется словом «нет» — пустые разделы приучают ревьюера пролистывать отчёт.

## О честности

Отчёт, который скрывает шероховатости, приносит вред дважды: сначала пропущенной проблемой, потом — тем, что следующий отчёт перестают читать внимательно. Если что-то сделано «пока так», покрыто тестами частично или основано на предположении, а не на проверенном факте — это идёт в отчёт словами. Ревьюер, который узнал о костыле из отчёта, потратит пять минут; ревьюер, который нашёл его сам, потратит час и перестанет доверять.
