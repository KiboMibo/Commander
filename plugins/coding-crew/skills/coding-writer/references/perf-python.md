# Производительность и память: Python

Порядок работы всегда один: **воспроизведи → измерь → почини → измерь снова**. В Python особенно легко ошибиться с диагнозом: код, который «должен быть медленным», часто не является узким местом, а настоящий виновник — сериализация, GIL или неудачный контейнер. Оба числа, до и после, полученные одинаково, идут в отчёт.

## Измерение

| Что выясняем | Чем |
|--------------|-----|
| Где уходит CPU | `python -m cProfile -o p.out app.py` + `snakeviz p.out`; `py-spy top --pid <PID>` на живом процессе |
| Построчно | `line_profiler` (`@profile` + `kernprof -l -v`) |
| Что держит память | `tracemalloc` (снапшоты + `compare_to`); `memray run app.py` |
| Память построчно | `memory_profiler` (`@profile`) |
| Рост во времени | `psutil.Process().memory_info().rss` с интервалом; `objgraph.show_growth()` |
| Микробенчмарк | `timeit`, `pytest-benchmark` |
| Запросы ORM | `django-debug-toolbar`, эхо SQLAlchemy, логирование запросов на запрос |

**tracemalloc для утечки** — самый короткий путь:

```python
import tracemalloc
tracemalloc.start(25)
snap1 = tracemalloc.take_snapshot()
...нагрузка...
snap2 = tracemalloc.take_snapshot()
for stat in snap2.compare_to(snap1, "lineno")[:15]:
    print(stat)
```

Строки с растущим `size_diff` и есть места аллокации того, что не освобождается.

## Типовые причины роста памяти

В Python редко бывают «утечки» в строгом смысле — счётчик ссылок собирает почти всё. Растёт память обычно потому, что что-то удерживает ссылку.

**Глобальные и уровня модуля коллекции.** Кеш-словарь, список результатов, реестр объектов, куда пишут и не чистят. Границы: `functools.lru_cache(maxsize=...)` (без `maxsize=None`), собственный LRU, TTL-кеш.

**`lru_cache` на методе.** Кеш живёт на классе и держит `self` каждого экземпляра — экземпляры не собираются никогда. Кешируй свободные функции или используй `cachetools` с явным ключом.

**Циклические ссылки с `__del__`.** Циклы сами по себе собираются `gc`, но объекты с финализаторами в старых версиях и объекты, попавшие в `gc.garbage`, — нет. Проверка: `gc.collect()` возвращает ненулевое число регулярно, `len(gc.garbage) > 0`. Разрывай циклы через `weakref`.

**Замыкания и колбэки.** Обработчик, зарегистрированный в глобальном диспетчере, держит захваченный контекст. Сигналы Django, подписки на события, `atexit` — снимай регистрацию так же явно, как ставил.

**Незакрытые ресурсы.** Файлы, соединения, курсоры, сессии `requests`, пулы. Всегда через `with` / `contextlib.closing`; для асинхронного — `async with`. Признак: `ResourceWarning` при запуске с `-W error::ResourceWarning`.

**Фрагментация от больших временных объектов.** Прочитанный целиком файл на 2 ГБ освобождается, но RSS не возвращается ОС. Лечится не «освобождением», а тем, чтобы не читать целиком: итерация по строкам, чанки, `pandas.read_csv(chunksize=...)`.

## Типовые причины медленного кода

**Не тот контейнер.** `x in list` — линейный поиск; `x in set`/`dict` — константа. Проверка вхождения в цикле по списку из 10 тысяч элементов — самая частая находка. `collections.deque` вместо `list.pop(0)` (последний — линейный). `bisect` для отсортированных.

**N+1 в ORM.** Обращение к связанному объекту в цикле. Django — `select_related` (FK, один join) / `prefetch_related` (M2M, второй запрос); SQLAlchemy — `joinedload`/`selectinload`. Сначала посчитай запросы на один вызов эндпоинта — число обычно объясняет всё.

**Конкатенация строк в цикле.** `s += part` даёт квадратичную сложность. Собирай в список и `"".join(parts)`.

**Работа поэлементно там, где есть векторизация.** Цикл по `DataFrame`/массиву вместо операции над столбцом; `df.apply` вместо векторного выражения; `iterrows` (самое медленное, что есть в pandas). В numpy/pandas выигрыш от векторизации — десятки раз, а не проценты.

**Пересоздание тяжёлого.** `re.compile` в теле функции, новая сессия `requests` на запрос, пересборка конфига, подключение к БД на вызов — на уровень модуля или в пул.

**Неверная модель параллелизма.** GIL означает: потоки помогают на I/O и не помогают на CPU. CPU-задачи — `multiprocessing`/`ProcessPoolExecutor` (но помни о цене pickle при передаче больших объектов), I/O — `asyncio` или потоки. Синхронный блокирующий вызов внутри `async def` останавливает весь событийный цикл — выноси в `asyncio.to_thread`.

**Глубокие атрибутные цепочки в горячем цикле.** `obj.a.b.c()` на миллионе итераций — каждый шаг это поиск в словаре. Вынеси в локальную переменную до цикла. Актуально только для действительно горячего кода — сначала профиль.

**`copy.deepcopy` по привычке.** Дорого и часто не нужно. Проверь, нужна ли вообще копия, или хватит поверхностной.
